# On the Book

책을 읽고, 그 안의 공간을 직접 걸어 보는 웹 서비스입니다. 사용자 화면과 실제로 연결된 관리자 화면을 함께 제공합니다.

Vercel에서는 사용자 화면과 관리자 화면을 별도 프로젝트로 배포합니다. 구성과 저장 방식은 [분리 배포 안내](docs/DEPLOYMENT.md)를 참고하세요.

## 바로 확인하기

- 사용자 화면: http://127.0.0.1:4173/client/
- 관리자 화면: http://127.0.0.1:4173/admin/
- 관리자 화면의 탭과 편집 위치는 주소에 남습니다. 예: http://127.0.0.1:4173/admin/models, http://127.0.0.1:4173/admin/books/alice?chapter=alice-2 (규칙은 [관리자 안내](docs/ADMIN-GUIDE.md#주소와-새로고침))
- 소개 페이지: http://127.0.0.1:4173/about (로컬에서는 `/client/about/`으로 이동합니다)

프로젝트 폴더에서 Node.js 22.12 이상으로 실행합니다. 처음 한 번 `.env.example`을 `.env`로 복사하고 Supabase 값을 채웁니다.

```powershell
npm install
npm run dev
```

로컬 서버도 운영과 같은 Supabase DB를 씁니다. 로컬 관리자에서 저장·공개하면 운영 사용자 화면에 바로 반영됩니다.

완성본으로 실행하려면:

```powershell
npm run build
npm start
```

## 현재 경험과 관리 기능

- 첫 화면은 상단 검색, 발견·전체 도서·이어 읽기 메뉴, 추천 배너, 도서 책장과 장면별 탐색으로 구성됩니다. [리디 만화](https://ridibooks.com/comics/ebook)의 검색·카테고리·여러 도서 코너와 [밀리의서재](https://www.millie.co.kr/)의 탐색 메뉴를 참고했습니다. 제목·작가 검색, 분류, 제목·출간연도 정렬을 지원하며 도서를 누르면 작품 상세 페이지가 열리고, 오른쪽 장면 패널의 '이 장면부터 걷기' 버튼으로 3D 공간에 들어갑니다. 읽던 작품은 마지막에 머문 장면에서 이어 읽을 수 있습니다. 회원가입·로그인·알림 메뉴는 없습니다.
- 기존 등록 도서만 표시하며 데모용 작품을 추가하지 않습니다. 공개 도서가 늘어나면 목록과 도서 수가 자동으로 확장됩니다. 분류는 관리자 도서 정보에서 정하며, 분류가 없는 예전 데이터는 앨리스 ‘판타지’, 오즈 ‘모험’, 그 밖의 책 ‘문학’으로 표시됩니다.
- 관리자가 올린 표지는 책장과 작품 상세·작품 소개 창에, 장면 썸네일은 장면 목록과 작품 상세의 장면 패널에 표시됩니다. 등록하지 않은 칸은 크기와 자리만 확보한 빈 칸으로 둡니다.
- 추천 배너(히어로)는 관리자 **홈 화면** 탭의 슬라이드 순서를 따릅니다. 사진이 있는 슬라이드는 사진이 카드 전체를 채우고 글이 그 위에 놓이며, 사진이 없으면 기본 그림으로 표시합니다. 슬라이드가 없거나 연결된 책이 모두 비공개이면 도서 보관함 순서의 앞 두 권을 보여 줍니다. 슬라이드를 누르면 연결된 책의 작품 상세를 엽니다.
- 장면 목록은 가로로 넘겨 볼 수 있고, 장면을 누르면 그 장면이 선택된 작품 상세가 열리고, 장면 패널이 그 장면의 이미지와 제목을 보여 줍니다. '이 장면부터 걷기' 버튼으로 그 장면의 3D 공간에 들어가고, 바로 아래 '이전 장면'·'다음 장면' 버튼으로 이웃 장면을 고릅니다. 이전·다음 버튼, 터치 스크롤, 목록에 초점을 둔 상태에서 방향키·Home·End를 지원합니다.
- 작품 상세 페이지에서 장면 목록(이 책의 여정)과 관리자가 쓴 저자 소개·책 소개를 확인하고 오른쪽 패널(휴대폰에서는 아래에서 올라오는 시트)에서 장면을 고른 뒤 '이 장면부터 걷기'로 3D 공간에 들어가며, 3D 공간 안에서는 **작품 소개** 창으로 작품 정보·장면 목록·원작 정보를 봅니다. 주소 `?book=<책>`은 작품 상세, `?book=<책>&scene=<장면>`은 그 장면이 선택된 작품 상세, `?book=<책>&chapter=<장면>`은 3D 공간입니다. 작품 상세에도 홈과 같은 띠 배너와 헤더(검색창 포함)가 있어, 검색어를 입력하고 Enter를 누르면 책장의 검색 결과로, 띠 배너를 누르면 책장의 장면 목록으로 갑니다. 작품 상세의 로고·책장 아이콘이나 3D 공간의 **책장으로**로 돌아오면 검색 조건과 위치가 유지되고 **이어 읽기**에서는 이 브라우저에서 방문한 작품을 볼 수 있습니다. 첫 진입 시 안내창은 자동으로 열리지 않으며 이용 방법 버튼으로 볼 수 있습니다.
- 트레일러는 아래쪽 **온더북 미리보기**에서 직접 열어 재생합니다. 미리보기 이미지는 표시하지 않으며 영상을 닫으면 재생을 멈춥니다.
- 영상 원본은 `public/trailer.mp4`, 실제 웹 재생본은 `public/trailer-web.mp4`, 재생 전 이미지는 `public/trailer-poster.jpg`입니다. 원본을 교체하면 웹 재생본과 이미지도 함께 갱신해야 합니다.
- 게임 요소 없이 넓은 공간을 자유롭게 이동합니다. 모델에 접근하면 애니메이션이 반복되고, 범위를 벗어나면 기본 자세로 돌아갑니다. 다시 접근하면 처음부터 재생됩니다.
- 각 챕터 기본 크기는 64×56이며 앨리스 여섯 장은 가로 384 길이로 이어집니다. 카메라는 캐릭터를 따라가며 모델에 접근하면 바닥 글귀를 볼 수 있도록 물러납니다. 범위를 벗어나면 돌아옵니다.
- 관리자는 **홈 화면** 탭에서 추천 슬라이드(최대 5개)의 연결 책·사진·사진 초점·문구를 편집하고, 도서 보관함에서 책을 끌어 사용자 책장의 순서를 정합니다. 도서 정보에서 표지와 분류를, 챕터 편집에서 장면 썸네일을 등록합니다. 이미지는 PNG 5MB 이하입니다.
- 관리자는 챕터 순서·공간 가로(40~120)·세로(40~100)·색 분위기·본문을 편집합니다. 모델을 등록·삭제·배치하고 위치·크기·회전·접근 거리(0.5~20)·기본 동작 또는 파일에 담긴 동작 이름을 지정합니다.
- 바닥 화살표가 모델들을 지나 다음 챕터로 안내합니다. 관리자는 화살표·손그림·바닥 글귀·카메라 여백을 설정하고 모델 설정에서 미리 볼 수 있습니다. 긴 본문은 페이지를 넘겨 읽습니다.
- 관리자 미리보기와 사용자 공간은 같은 좌표와 지형을 사용합니다. 임시 저장과 공개는 분리됩니다.
- 관리자는 새로고침하거나 주소를 직접 입력해도 보던 탭, 편집 중인 책·챕터·선택한 오브젝트, 열린 창, 검색 조건, 독자 체험으로 돌아옵니다. 새로고침과 뒤로·앞으로 가기에서는 목록의 스크롤 위치도 되살립니다. 뒤로 가기는 열린 창을 닫거나 이전 화면으로 돌아가며, 저장하지 않은 변경이 있으면 편집기를 떠나기 전에 확인합니다. 저장하지 않은 편집 내용은 새로고침으로 되살리지 않습니다.
- 수집·보상·행동 버튼·열쇠 조건·크기 퍼즐·잠긴 문·완료 화면은 제거했습니다. 게임 진행 기록은 읽거나 저장하지 않고 마지막으로 방문한 챕터만 기억합니다.

## 확인 순서

1. 사용자 화면에서 표지를 눌러 작품 상세를 열고 '이 장면부터 걷기'를 누른 뒤 땅을 누르거나 방향키로 이동합니다. 휴대폰에서는 방향 버튼도 사용할 수 있습니다.
2. 모델 가까이에서 움직임을 보고, 멀어졌다가 다시 접근합니다. 오른쪽으로 계속 걸으면 다음 챕터로 이어집니다. 지도에서 원하는 챕터로 바로 이동할 수도 있습니다.
3. 관리자 **챕터와 본문**에서 공간 크기를 조절합니다. **모델 설정**에서 위치와 접근 거리, 애니메이션을 조절하고 미리 봅니다.
4. **임시 저장** 후 **사용자 화면에 공개**하고 사용자 화면을 새로고침합니다.
5. 새 모델은 **3D 모델 보관함 → 모델 등록 → 책과 챕터 → 모델 배치** 순서로 추가합니다.

## 데이터와 원본 보관

- `server`: 저장·공개·업로드를 처리하는 로컬 서버
- `shared`: 공통 3D 화면, 모델 생성, 데이터 검증, 스타일
- `client/about`: 브랜드 시안 sample-02를 옮긴 소개 페이지. 출처와 에셋은 `docs/ABOUT-PAGE.md`를 참고하세요.
- `supabase/migrations`: DB 구조. 관리 항목은 표 한 줄에 하나씩 들어갑니다(`books`·`chapters`·`placements`·`models`·`hero_slides`). 공개할 때마다 공개본이 `publications`에 남고, 독자 화면은 가장 최근 공개본을 읽습니다.
- Supabase 저장소 `uploads` 버킷: 업로드한 GLB와 PNG(표지·장면 썸네일·히어로 사진·바닥 그림), 소개 페이지 여정 모델과 사진. 파일마다 `assets` 표에 크기·SHA-256·딸린 모델이나 책이 기록됩니다. 보관함에서 삭제해도 이미 공개된 장면의 원본을 보존하기 위해 파일을 즉시 지우지 않습니다.
- Supabase 저장소 `archive` 버킷: 블렌더 원본(`.blend`)과 도면. 앱 화면에는 나오지 않습니다.
- `scripts/blender/export-web-glb.py`: 블렌더 모델을 관리 화면 "모델 등록"에 올릴 GLB와 썸네일 PNG로 내보내는 스크립트. 촬영용 바닥·도면을 빼고, GLB가 담지 못하는 절차적 재질을 색으로 옮기고, 꼭짓점을 4만 개 안팎으로 줄입니다.
- `docs/REFERENCE-RESEARCH.md`: 직접 조작한 참고 사이트 조사 기록
- `tests`: 독립된 임시 데이터로 실행하는 저장·업로드·브라우저 검증

3D 모델·블렌더 원본·작업 파일은 프로젝트 폴더에 두지 않습니다. `.gitignore`가 막고, `npm test`의 점검이 폴더 안의 모델 파일을 찾으면 실패합니다. Supabase 무료 요금제에는 자동 백업이 없으므로, 필요하면 대시보드에서 표와 저장소 파일을 내려받아 보관합니다. 사용자 개인 탐험 기록은 해당 브라우저에 저장되어 다른 기기와 동기화되지 않습니다.

## 관리자 비밀번호

현재 서버는 `127.0.0.1`에만 연결되므로 다른 컴퓨터에는 공개되지 않습니다. 로컬에서도 비밀번호가 필요하면 `.env`의 `ADMIN_PASSWORD`에 직접 정한 긴 비밀번호를 넣고 서버를 다시 실행합니다.

비밀번호를 설정한 경우 관리자 데이터·저장·업로드는 로그인 세션이 있어야 접근할 수 있습니다. 세션은 DB에 저장되어 서버를 다시 켜도 유지되고 8시간 후 만료됩니다. 계정별 권한이나 회원 가입은 포함하지 않았습니다.

## 현재 범위

- 로컬 실행과 Vercel 분리 배포를 지원합니다. 로컬과 Vercel 모두 같은 Supabase DB·저장소를 쓰며, Vercel 배포는 관리자 비밀번호를 사용합니다. 자체 도메인과 계정별 권한 구성은 포함하지 않습니다.
- 기본 본문은 원작을 직접 한국어로 축약·각색한 샘플입니다. 책 전체의 완역은 아닙니다.
- 현재 배경은 모눈종이 바닥과 손그림이 놓인 이어지는 평지입니다. 지형 굴곡을 직접 만드는 편집기는 포함하지 않습니다. 서사 소품을 자동으로 추가하지 않고 관리자가 배치한 모델을 표시합니다.
- Supabase 대시보드에서 표의 값을 직접 고칠 수 있습니다. 그 전에 열어 둔 관리자 창에서 저장하면 덮어쓰는 대신 새로고침을 요청합니다. 저장 형식이 바뀐 새 관리자로 한 번 저장하면, 그보다 오래된 관리자에서는 저장이 거부됩니다.
- 업로드는 텍스처와 자료가 한 파일에 들어 있는 GLB 2.0, 최대 25MB를 지원합니다. 뼈대나 동작이 없는 정적 모델도 올릴 수 있으며, 정적 모델은 기본 동작(동작 없음 포함)으로 배치합니다. 외부 파일을 참조하는 모델은 허용하지 않습니다. 압축 전용 디코더를 요구하는 모델은 일반 GLB로 다시 내보내 주세요.
- 3D 장면은 그래픽 가속을 지원하는 브라우저가 필요합니다. 불가능한 환경에서는 설명과 본문 읽기 대안을 제공합니다.
- 글꼴은 온라인 글꼴 서비스를 사용하며 연결되지 않으면 시스템 글꼴로 표시됩니다.
- 향후 외부 운영에는 관리 계정 체계와 백업 정책을 마련해야 합니다. Supabase 무료 요금제는 일주일 동안 요청이 없으면 프로젝트를 멈추고, 파일 저장 1GB와 월 전송량 한도가 있습니다. 장면 모델이 10~21MB라 방문이 늘면 전송량 한도에 먼저 닿습니다.

브라우저 검증은 설치된 Microsoft Edge를 사용합니다. 일부 검사는 커밋된 `docs/screenshots`, `docs/floor-evidence`의 화면과 `docs/browser-results.json`을 다시 만들므로, 화면을 바꾸는 작업이 아니면 실행 뒤 되돌립니다. 다른 환경은 `tests/browser.mjs`의 브라우저 채널을 해당 환경에 맞게 바꿔야 합니다. 테스트는 서버마다 운영체제가 고른 빈 포트와 OS 임시 폴더의 데이터를 사용하며 Supabase DB를 바꾸지 않습니다. 서버는 실제로 연 포트를 자기를 띄운 테스트에만 알려 주므로, 여러 세션이나 작업 폴더에서 동시에 실행해도 다른 실행의 서버에 붙지 않습니다. 예외는 둘입니다. `npm run test:about`은 소개 페이지 여정 자료를 Supabase에서 읽어 임시 폴더로 복사합니다. `tests/supabase.mjs`는 실제 DB에 대고 내용이 바뀌지 않는 저장과 시험 업로드를 한 뒤, 올린 파일을 지웁니다.

관리자 주소 검증은 비밀번호를 켠 서버에서 깊은 주소 제공과 404, 로그인 뒤 원래 주소, 탭·검색·편집기·창의 새로고침과 뒤로·앞으로 가기, 잘못된 주소 보정, 독자 체험·패널 접힘·스크롤 유지를 확인합니다. 책장 검증의 18권 확장 화면과 표지·썸네일·사진 히어로 화면은 브라우저의 테스트 응답으로만 만들어지며 실제 저장 데이터는 변경하지 않습니다. 홈 화면 관리 검증은 관리자에서 표지·분류·책 순서·장면 썸네일·슬라이드를 바꾸고 미리보기·공개·비공개 전환·책 삭제까지 확인합니다. 이전 `tests/qa-uat` 시나리오 중 소개 화면의 시작 버튼·자동 안내창을 전제로 한 항목은 현재 책장 흐름에 적용되지 않습니다.

모델 접근 시 글귀는 화면 오른쪽의 반투명 흐림 배경에 표시되며 캐릭터와 모델은 왼쪽에 함께 보입니다. 관리자의 미리보기에도 같은 구도가 적용됩니다.
