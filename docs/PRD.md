# On the Book 제품 요구사항 문서 (PRD)

- 상태: 초안 v0.1 — 검토 및 합의 필요
- 작성일: 2026-09-21
- 대상: 서비스 기획, 디자인, 개발, 콘텐츠 운영 담당자
- 작성 근거: 프로젝트 내 서비스 소개, 관리자 안내, 기능 변경 및 전환 설계 문서

> 이 문서는 기존 문서에 흩어진 제품 요구사항을 정리한 초안이다. 현재 구현 전체를 새로 검증한 결과나 출시 승인을 뜻하지 않는다. 기존 기능을 기준으로 한 요구사항과 향후 계획, 추가 합의가 필요한 제안을 구분한다.

## 1. 제품 개요

On the Book은 책을 읽으며 이야기 속 공간을 직접 걸어 보는 웹 서비스다. 독자는 책을 선택하고 연결된 챕터를 자유롭게 이동하며, 모델에 가까이 다가가 움직임을 보고 본문을 읽는다. 관리자는 별도의 편집 화면에서 책, 본문, 공간, 모델을 구성하고 독자 체험으로 확인한 뒤 공개한다.

핵심 경험은 자유로운 이동과 읽기다. 수집, 보상, 퍼즐 해결이나 잠긴 문 통과를 독서의 조건으로 삼지 않는다.

## 2. 해결하려는 문제와 목표

다음 문제 정의는 기존 기능 방향을 바탕으로 정리한 가설이며, 독자와 운영자 인터뷰로 확인이 필요하다.

| 대상 | 문제 가설 | 제품 목표 |
| --- | --- | --- |
| 독자 | 글과 이야기 공간이 분리되어 있어 장면을 탐색하며 읽기 어렵다. | 이동, 장면 반응, 본문 읽기가 자연스럽게 이어지도록 한다. |
| 독자 | 복잡한 게임 규칙이 읽기 흐름을 방해할 수 있다. | 별도 미션 없이 원하는 속도로 이동하고 읽도록 한다. |
| 콘텐츠 관리자 | 본문과 3D 장면을 수정할 때 개발 작업에 의존하기 쉽다. | 편집 화면에서 콘텐츠를 배치하고 저장·체험·공개하도록 한다. |
| 콘텐츠 관리자 | 편집 결과가 독자 화면에서 다르게 보이거나 미완성 내용이 노출될 수 있다. | 실제 독자와 같은 경험으로 확인하고, 임시 저장과 공개를 분리한다. |

주요 독자의 연령, 이용 목적, 교육 기관 활용 여부와 초기 콘텐츠 선정 기준은 아직 확정하지 않는다.

## 3. 사용자와 핵심 이용 흐름

### 3.1 독자

1. 공개된 책 목록에서 책을 선택한다.
2. 책 속 공간에 들어가 화면 조작 또는 키보드로 이동한다.
3. 모델에 가까이 다가가 애니메이션을 보고, 챕터의 메인 모델 주변에서 본문을 읽는다.
4. 긴 본문은 페이지를 넘기거나 본문 영역을 스크롤해 읽는다.
5. 이어진 공간을 걸어 다음 챕터로 가거나 지도에서 챕터를 선택한다.
6. 나중에 같은 브라우저로 돌아왔을 때 마지막으로 방문한 챕터를 이어 본다.

### 3.2 콘텐츠 관리자

1. 관리자 화면에서 책을 찾거나 새 도서 초안을 만든다.
2. 도서 정보, 출처와 권리 정보, 챕터와 본문을 작성한다.
3. 애니메이션 모델과 바닥 이미지를 등록하고 공간에 배치한다.
4. 메인 모델, 접근 범위, 충돌 범위와 본문 표시를 조정한다.
5. 독자 체험으로 이동·애니메이션·본문·카메라를 확인한다.
6. 임시 저장하고 공개 조건을 확인한 뒤 사용자 화면에 공개한다.

## 5. 독자 기능 요구사항

아래 확인 기준은 앞으로 검수할 기준이며, 이 문서 작성 과정에서 통과를 확인했다는 뜻은 아니다.

| 번호 | 요구사항 | 확인 기준 |
| --- | --- | --- |
| R-01 | 독자는 공개된 책만 선택할 수 있어야 한다. | 미공개 도서는 독자 목록과 직접 접근에서 노출되지 않는다. |
| R-02 | 독자는 공간 안에서 자유롭게 이동할 수 있어야 한다. | PC에서 화면 조작과 방향키·WASD, 모바일에서 화면 방향 버튼으로 이동할 수 있다. |
| R-03 | 챕터는 관리자가 정한 순서로 연결되어야 한다. | 미션 수행이나 모델 발견 없이 다음 챕터로 걸어갈 수 있고 지도에서도 챕터를 선택할 수 있다. |
| R-04 | 각 모델은 접근에 반응해야 한다. | 접근 범위 안에서 지정 동작을 반복하고, 벗어나면 기본 자세로 돌아가며 재접근하면 처음부터 재생한다. |
| R-05 | 메인 모델은 본문 읽기와 연결되어야 한다. | 메인에 접근하면 본문과 독서용 카메라가 작동하고, 보조 모델 접근은 애니메이션만 작동한다. |
| R-06 | 긴 글도 화면 크기에 맞게 읽을 수 있어야 한다. | 페이지 이동과 본문 스크롤이 가능하고 모바일에서도 페이지 버튼을 사용할 수 있다. |
| R-07 | 이동 경로는 다음 읽기 지점을 안내해야 한다. | 자동 화살표는 메인 모델을 경유하며 애니메이션 반응 영역 밖에 표시된다. |
| R-08 | 읽기 위치를 같은 브라우저에서 이어 볼 수 있어야 한다. | 마지막 방문 챕터를 복원하며 과거 게임 진행 기록을 읽거나 저장하지 않는다. |
| R-09 | 설정된 충돌 영역을 통과하지 않아야 한다. | 이동 중 모델의 고정된 원형 충돌 영역을 피하며 관리자 체험에서도 같은 결과를 보인다. |

## 6. 관리자 기능 요구사항

| 번호 | 요구사항 | 확인 기준 |
| --- | --- | --- |
| A-01 | 도서를 찾고 초안을 생성·편집할 수 있어야 한다. | 제목 검색과 공개 대상 필터를 제공하고, 제목만으로 초안을 만든 뒤 표지·저자·소개·출처·권리 정보를 완성할 수 있다. |
| A-02 | 챕터의 내용과 순서를 관리할 수 있어야 한다. | 챕터 추가·삭제·순서 변경, 공간 크기·분위기·본문 편집이 가능하며 공개 후 독자 화면에 반영된다. |
| A-03 | 애니메이션 모델을 등록하고 배치할 수 있어야 한다. | 새 등록·배치는 뼈대와 뼈대 애니메이션이 있는 3D 모델 파일(GLB)을 사용하고, 보관함에서 미리 본 뒤 공간으로 끌어 배치할 수 있다. |
| A-04 | 배치 결과를 세밀하게 수정할 수 있어야 한다. | 위치·높이·크기·회전·동작·접근 범위·충돌 범위를 조정하고 복제·삭제·실행 취소·다시 실행을 할 수 있다. |
| A-05 | 메인 모델과 보조 모델을 구분해야 한다. | 첫 배치는 메인이 되고 이후 배치는 보조가 된다. 메인 변경 시 본문과 자동 경로의 연결 대상도 바뀌며, 메인 삭제 시 남은 모델에서 대체 메인을 선택한다. |
| A-06 | 반응 범위가 겹치는 새 배치를 제한해야 한다. | 배치·이동·반경 변경 시 이웃 챕터까지 수평 범위 겹침을 검사한다. 기존 배치는 임의로 이동하지 않는다. |
| A-07 | 바닥 이미지를 배치하고 편집할 수 있어야 한다. | 기본 이미지와 등록한 PNG를 배치하고 위치·높이·크기·회전을 변경하거나 삭제할 수 있다. 직접 배치한 이미지는 지정 위치를 유지한다. |
| A-08 | 독자와 같은 방식으로 편집 내용을 체험할 수 있어야 한다. | 현재 편집 공간에서 이동·충돌·접근 반응·본문을 확인하고, 체험 종료 시 편집 시점과 선택 상태로 돌아온다. 체험만으로 저장·공개하거나 독자 기록을 바꾸지 않는다. |
| A-09 | 임시 저장과 공개를 분리해야 한다. | 임시 저장은 관리자 작업만 보존한다. 공개를 실행해야 독자에게 반영되며, 이미 열린 독자 화면은 새로고침 후 확인한다. |
| A-10 | 미완성 도서를 공개하지 않아야 한다. | 공개 대상 도서에는 저자와 권리 정보가 있고 모든 챕터에 메인 모델이 있어야 한다. 빈 챕터의 초안 저장은 허용한다. |
| A-11 | 저장 실패나 동시 수정 충돌을 알려야 한다. | 저장 성공으로 오인시키지 않고 재시도나 새로고침 등 다음 행동을 안내한다. 편집 내용 보존 방식은 실패 상황별로 검수한다. |

### 후속 계획: 편집기 안내

첫 방문 시 모델 보관함, 바닥 이미지, 공간 조작, 도구, 챕터, 속성, 저장과 공개를 순서대로 안내한다. 안내를 마치면 다음 방문에 자동으로 반복하지 않고 도움말에서 다시 볼 수 있어야 한다. 기존 전환 설계에 따른 계획이며 핵심 기능의 현재 완료 상태와 구분해 관리한다.

## 7. 콘텐츠와 운영 규칙

- 공개 도서에는 저자, 출처와 권리 정보를 관리한다. 실제 콘텐츠 사용 권한 확인 절차와 담당자는 추가 합의가 필요하다.
- 기존 문서상 파일 제한은 PNG 5MB·가로세로 각각 4096 이하, GLB 25MB다. 허용 형식이나 크기를 벗어난 파일은 등록을 거부하고 이유를 안내한다.
- 새 모델 배치 기준을 충족하지 않는 기존 기본 모델은 기존 장면 보존을 위해 유지하되 새 배치는 제한한다.
- 공개된 장면이 참조하는 모델 파일은 보관함 항목 삭제만으로 즉시 제거하지 않는다.
- 관리자 편집 화면과 독자 화면은 같은 배치, 접근 범위, 충돌 규칙을 사용한다.
- 자동 경로는 메인 모델 중심이라는 관리자 안내의 후반 규칙을 기준으로 한다. 앞부분에 남아 있는 수동 경유지 편집 설명과 실제 동작의 일치 여부는 별도로 확인한다.

## 8. 품질 요구사항

| 영역 | 요구사항 및 확인 기준 |
| --- | --- |
| 모바일 | 독자 화면은 세로 화면에서도 이동 버튼·본문·페이지 버튼이 겹치지 않고 사용 가능해야 한다. 모바일 관리자 편집 지원 수준은 별도 결정한다. |
| 접근성 | 키보드 이동을 지원하고 동작 줄이기 설정에서는 모델 애니메이션을 정지한다. 전체 화면의 키보드 접근과 보조 읽기 도구 지원 수준은 추가 검수한다. |
| 접근 제한 | 배포된 관리자 화면은 인증된 관리자만 편집·저장·공개할 수 있어야 한다. 미공개 내용과 파일은 독자에게 노출되지 않아야 한다. |
| 데이터 보존 | 임시 저장과 공개 데이터는 구분해 보존하고, 동시 저장 충돌로 다른 작업을 조용히 덮어쓰지 않아야 한다. |
| 오류 안내 | 연결·저장·모델 불러오기 실패를 사용자가 이해할 수 있는 말로 안내한다. 기능별 재시도와 복구 동작은 검수 항목으로 확정한다. |
| 성능 | 대표 도서와 실제 모바일 기기에서 초기 진입, 이동, 본문 표시를 측정한다. 허용 시간·기기·모델 복잡도 기준은 측정 후 합의하며 현재 수치를 보장하지 않는다. |

## 9. 성공 지표 제안

아래 지표는 제안이며 수집 여부, 기준값과 목표 수치는 미정이다. 측정 도입 시 수집 항목과 개인정보 처리 범위도 함께 정한다.

| 목표 | 측정 후보 | 측정 방법 |
| --- | --- | --- |
| 독자가 쉽게 시작한다. | 책 선택 후 첫 본문 읽기까지 걸린 시간과 도달 비율 | 독자 사용성 테스트 또는 합의된 이용 기록 |
| 읽기 흐름이 이어진다. | 다음 챕터 이동 비율, 이동·본문 조작 중 막힌 사례 수 | 관찰 테스트와 이용 기록 |
| 관리자가 스스로 공개한다. | 도서 초안부터 정상 공개까지 걸린 시간과 도움 요청 횟수 | 신규 관리자 과제 수행 테스트 |
| 편집 결과를 신뢰할 수 있다. | 체험·공개 화면 불일치, 저장 실패, 데이터 손실 사례 수 | 검수 기록과 운영 오류 기록 |

오래 머문 시간만으로 독서 만족도를 판단하지 않는다. 읽기 편의성과 이야기 이해에 대한 사용자 피드백을 함께 확인한다.

## 10. 검수 및 공개 판단 기준

다음 조건을 모두 확인한 뒤 공개 여부를 판단한다. 이 목록은 검수 계획이며 현재 통과 기록을 대신하지 않는다.

1. 대표 도서에서 책 선택 → 이동 → 메인 접근 → 본문 읽기 → 다음 챕터 → 재방문 흐름이 이어진다.
2. 관리자에서 도서·챕터 생성 → 모델·이미지 배치 → 독자 체험 → 임시 저장 → 공개 흐름이 완료된다.
3. 임시 저장만 했을 때 공개 내용은 바뀌지 않으며, 공개 후 새로고침하면 독자 화면에 반영된다.
4. 공개 정보 누락, 메인 없는 챕터, 잘못된 업로드, 범위 겹침을 적절히 제한한다.
5. 미인증 편집과 미공개 데이터 접근을 차단하고 저장 실패·충돌 시 사용자가 다음 행동을 알 수 있다.
6. PC와 합의된 실제 모바일 기기에서 이동·본문·애니메이션·충돌을 확인하며 동작 줄이기 설정을 검수한다.
7. 기술 전환을 진행한다면 기존 콘텐츠와 읽기 위치, 핵심 이용 흐름이 유지되는지 별도로 확인한다.

| 기기와 성능 | 지원 브라우저·실기기, 최대 콘텐츠 규모, 초기 진입과 이동 성능의 합격 기준 |

| 미검증 환경 | 실제 모바일 장시간 성능과 복잡한 제작 모델, 다양한 브라우저에서 추가 검수 필요 |
