### V08

**공백 제목의 도서가 만들어지고 저장 단계에서 영문 오류가 표시됨**

- 재현: 관리자 → 새 도서 추가 → 책 제목에 공백 3개 → 책 만들기 → 임시 저장
- 실제: 제목이 비어 보이는 책이 만들어진다. 저장 응답은 400이며 “Too small: expected string to have >=1 characters”가 표시된다.
- 기대: 공백을 제거한 제목이 비어 있으면 생성 전에 한국어로 입력을 요청한다.
- 사용자 영향: 이름이 없는 책의 편집 화면에 들어간 뒤 저장이 실패한다. 다른 미저장 작업과 함께 저장할 때 원인 파악이 어렵다.
- 권장 조치: 책 생성과 수정 시 공백 제목을 즉시 검증하고 저장 오류를 한국어로 안내한다.

### E08

**챕터 추가창을 닫아도 빈 챕터가 남음**

- 재현: 도서 편집 → 챕터 추가 → 열린 설정창의 닫기 버튼
- 실제: 6개였던 챕터가 7개로 남는다. 코드와 기존 검사에서는 “챕터 추가”를 누를 때 즉시 생성하는 구조다.
- 기대: 확정 전에 취소하는 흐름을 수용 기준으로 채택할지, 즉시 생성한다는 안내를 유지할지 결정한다.
- 사용자 영향: 추가를 취소했다고 생각하면 빈 챕터가 의도치 않게 남을 수 있다. 즉시 생성 후 설정하는 방식이라면 안내와 취소 방식의 검토가 필요하다.
- 권장 조치: 생성 확정/취소를 구분하거나, 닫아도 챕터가 남는다는 점과 실행 취소 방법을 알린다.

[걸킨 시나리오](features/admin-edit.feature) · [화면](evidence/E08.png) · [실행 기록](recheck-issues.json)

### J02

**저장 중 추가한 수정 사항까지 저장된 것처럼 표시됨**

- 재현: 책 제목을 “QA 첫 저장”으로 변경 → 느린 저장 요청 시작 → 응답 전에 제목을 “QA 저장 중 추가 편집”으로 변경 → 저장 응답 완료
- 실제: 서버에는 첫 제목만 저장되지만 화면에는 두 번째 제목과 “변경사항 저장됨”이 함께 표시된다.
- 기대: 현재 화면에 저장되지 않은 추가 편집이 남으면 “저장하지 않은 변경사항”으로 표시한다.
- 사용자 영향: 실제로 저장되지 않은 최신 편집 내용을 사용자가 저장 완료로 오인할 수 있다. 나가기 경고는 별도로 작동하므로 데이터 유실을 확정한 것은 아니다.
- 권장 조치: 저장 응답 이후에도 현재 편집 내용과 저장된 내용을 비교해 저장 상태 문구를 표시한다.

### Z03

**기본 제공 모델의 이름과 정보를 수정할 수 없음**

- 재현: 3D 모델 보관함 → 하얀 토끼 편집 → 모델 이름 변경 → 변경 적용
- 실제: 기본 모델의 종류가 GLB 선택으로 표시되고 파일 업로드를 요구해 기존 모델의 정보 변경이 막힌다.
- 기대: 기본 모델의 종류를 보존하면서 이름·색상·사용 권한 정보를 수정한다.
- 사용자 영향: 기본 토끼·나무 같은 모델에서 편집 기능을 열 수 있지만 정보 변경을 적용하지 못한다.
- 권장 조치: 기존 기본 모델을 편집할 때 원래 종류를 유지하고 GLB 파일 필수를 적용하지 않는다.

## 실행 환경과 검증 방법

- 브라우저 자동 조작 도구: Playwright MCP 1.63.0-alpha-2026-08-31; Microsoft Edge 152.0.4191.66, 별도 브라우저 세션. 일반 Playwright 테스트 실행으로 대체하지 않고 MCP의 화면 실행 도구를 호출했습니다.
- 실행 대상: 현재 저장소의 client/admin 전체 빌드와 책 2권·챕터 9개의 기존 데이터 사본. 로그인 보호 환경은 별도 포트와 별도 데이터 사본으로 실행했습니다.
- 걸킨 문서를 먼저 생성한 뒤 클릭·입력·드래그·파일 등록·키보드로 시나리오를 실행했습니다. 저장·공개 결과는 실제 응답 및 사용자 화면으로 확인했습니다. 외부 서비스에는 배포하거나 공개하지 않았습니다.
- 느린 응답·일시 장애·3D 미지원·저장 공간 오류는 브라우저에서 의도적으로 재현했습니다. 새 책·새 모델·삭제·공개는 테스트 사본에서만 실행했습니다. 각 시나리오 전에 사본의 데이터를 초기화하고 별도 브라우저 문맥으로 격리했습니다.
- 초기 도구 연결은 기록 수집기의 실행 환경 차이로 종료되었습니다. 수집기를 보완하고 별도 Playwright MCP 연결에서 전부 실행했습니다. 대기·초점 판정·사전 데이터 설정 때문에 발생한 검사 오류는 보완 후 재실행했고, 이력은 원본 결과에 남겼습니다. 제품 파일은 수정하지 않았습니다.

## 확인할 것과 남은 범위

- 원본 작업 데이터 보존: **내용 해시 일치, 변경 없음**. 테스트 결과와 재실행 도구만 추가했습니다.
- 사용자 모바일 화면, 이동 버튼, 일반 관리자 화면의 4개 크기 검사는 통과했습니다. 다만 390px 관리자 편집 화면은 여러 패널이 빽빽하게 겹칩니다. [작은 편집 화면](evidence/P09.png)을 보고 실제 휴대폰에서 작업 편의성을 확인하는 것이 좋습니다. 이 관찰은 기능 실패 수에 포함하지 않았습니다.
- 실제 배포 환경의 저장소·분리 도메인·권한 설정, 실제 iOS/Safari·Firefox, 실기기 터치·음질, 대규모 동시 사용자 부하, 장시간 메모리 누수는 이번 실행 범위에 포함하지 않았습니다. 3D 충돌의 수치 검증은 기존 기본 검사에서, 화면 이동과 장면 전환은 이번 브라우저 검사에서 확인했습니다.
- 보조 검사: 기본 검사 24개 통과. 전체 빌드 통과. client/admin 개별 빌드는 별도 산출 폴더로 확인했습니다. 공통 3D 묶음 크기 경고는 별도 성능 개선 후보입니다.
