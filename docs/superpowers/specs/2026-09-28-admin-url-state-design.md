# On the Book: 관리자 주소(경로·쿼리) 상태 설계

작성일 2026-09-28. 관리자 화면(admin)이 보고 있는 위치를 주소의 경로 매개변수와 쿼리 매개변수에 담아, 새로고침과 직접 주소 입력에 대응하는 설계다.

## 1. 배경과 목표

현재 관리자는 탭(`tab`), 편집기 여부(`inEditor`), 편집 중인 책(`bookId`)·챕터(`chapterId`)·선택한 오브젝트(`placementId`), 모델 검색어(`query`)를 `admin/main.js` 모듈 변수에만 둔다. 주소는 `/admin/` 하나라서 어디에서 새로고침하든 도서 보관함 첫 화면으로 돌아간다. 도서 보관함의 검색어와 상태 필터는 DOM 에만 있어 화면을 다시 그릴 때마다 풀리고, 월드 편집기의 떠 있는 패널은 변경을 적용할 때마다 모두 다시 펼쳐진다. 사용자 화면(client)은 이미 `?book=&chapter=` 쿼리와 `popstate` 를 쓴다(`client/main.js`).

사용자 요청(2026-09-28): 상위 페이지, 상세 페이지, 드로어 컴포넌트에서 새로고침하면 그 자리에 머물고, 주소를 직접 입력해도 그 자리가 열려야 한다. 이를 위해 parameter 와 query parameter 를 설정한다. 이 앱에는 옆에서 밀려 나오는 드로어가 없고 가운데 뜨는 대화상자(`shared/ui.js` 의 `modal()`)가 그 역할을 하므로, 드로어는 대화상자로 읽는다.

사용자가 고른 것
- 주소 구조: 경로 + 쿼리. 탭과 편집 중인 책은 경로, 나머지는 쿼리.
- 추가 범위: 검색·필터 조건, 독자 체험 모드, 편집기 패널 접힘, 스크롤 위치 전부.
- 스크롤 위치와 패널 접힘은 주소 문자열에 드러내지 않고 기억한다(3.5절).
- 뒤로 가기: 페이지와 대화상자 단위로 기록을 쌓는다. 독자 체험은 기록을 쌓지 않는다.
- 저장하지 않은 편집 내용은 새로고침으로 되살리지 않는다.

기준 스택은 현재 admin(Vite 멀티 페이지 + 바닐라 JS)이다. 경로는 전환 스펙(`2026-09-11-react-next-migration-design.md`) 4·9절의 Next 관리자 경로(`app/admin/page.tsx`, `app/admin/home`, `app/admin/models`, `app/admin/settings`)와 같게 잡아 전환 뒤에도 주소가 유지되게 한다.

## 2. 범위와 비범위

범위
- 네 탭(도서 보관함·홈 화면·3D 모델 보관함·공개 및 안내)과 월드 편집기의 주소.
- 편집기의 챕터, 선택한 오브젝트, 독자 체험, 모델 보관함 패널 검색어.
- 내용을 보여 주거나 편집하는 대화상자 7종(3.3절).
- 도서 보관함 검색어·상태 필터, 모델 보관함 검색어.
- 스크롤 위치, 편집기 패널 접힘.
- 뒤로 가기·앞으로 가기, 로그인 뒤 원래 위치, 잘못된 주소 보정.
- 로컬 서버(개발·완성본)와 Vercel 관리자 배포의 깊은 경로 제공.
- 검사, README·관리자 안내·배포 안내·전환 스펙 반영.

비범위
- 저장하지 않은 편집 내용 복원. 새로고침 전 경고(`beforeunload`)는 지금처럼 둔다.
- 삭제 확인, 나가기 확인, 메인 모델 교체 같은 한 번 쓰는 확인 창.
- 편집 도구(이동·방향·크기·범위), 격자 단위, 카메라 시점, 독자 체험 속 캐릭터 위치.
- 탭 버튼과 표지 타일을 링크(`<a>`)로 바꾸는 일. 새 탭 열기를 쉽게 하면 여러 탭 동시 편집과 저장 충돌을 부르므로 버튼을 유지한다. 주소 표시줄의 주소는 복사해 쓸 수 있다.
- 여러 탭의 주소 동기화. 동시 편집은 지금의 저장 충돌 검사에 맡긴다.
- 사용자 화면(client) 주소 변경. 쓰지 않는 옛 편집 화면 코드(`booksView`, `bindBooks`, `inspectorView`, `makePreview`, `addPlacement`, `previewClient`) 정리.
- React·Next 전환.

## 3. 주소 규칙

### 3.1 경로

| 경로 | 화면 |
| --- | --- |
| `/admin/` | 도서 보관함. `/admin` 과 Vercel 관리자 배포의 `/` 로 들어와도 이 화면을 보여 주고 주소를 `/admin/` 으로 고친다 |
| `/admin/home` | 홈 화면 |
| `/admin/models` | 3D 모델 보관함 |
| `/admin/settings` | 공개 및 안내 |
| `/admin/books/:bookId` | 월드 편집기. `:bookId` 는 `encodeURIComponent` 로 넣는다 |

끝 빗금이 붙은 `/admin/home/` 같은 주소도 같은 화면으로 읽고 빗금 없는 주소로 고친다. 그 밖의 `/admin/…` 경로는 서버가 404 를 준다(6.6절). 앱이 그런 경로를 받으면 도서 보관함으로 읽는다.

### 3.2 쿼리

| 이름 | 화면 | 값 |
| --- | --- | --- |
| `q` | 도서 보관함 | 제목 검색어 |
| `q` | 3D 모델 보관함 | 모델 이름 검색어 |
| `q` | 월드 편집기 | 모델 보관함 패널 검색어 |
| `status` | 도서 보관함 | `draft`(비공개 초안) 또는 `public`(공개 대상). 없으면 모든 도서 |
| `chapter` | 월드 편집기 | 보고 있는 챕터 id. 편집기 주소에는 항상 넣는다. 독자 체험 중에는 체험이 보여 주는 챕터 |
| `object` | 월드 편집기 | 선택한 모델 배치 또는 바닥 이미지의 id |
| `mode` | 월드 편집기 | `reader`(독자 체험) |
| `modal` | 화면마다 | 3.3절 |
| `id` | 화면마다 | `modal` 이 가리키는 대상 id(3.3절) |

### 3.3 대화상자

| `modal` | 화면 | `id` | 여는 곳 |
| --- | --- | --- | --- |
| `new-book` | 도서 보관함 | 없음 | 새 도서 추가 |
| `book` | 월드 편집기 | 없음(경로의 책) | 도서 정보 |
| `chapter` | 월드 편집기 | 챕터 id | 챕터 편집(연필), 챕터 추가 |
| `new-model` | 3D 모델 보관함, 월드 편집기 | 없음 | 모델 등록, 모델 보관함 패널의 ＋ 등록 |
| `model` | 3D 모델 보관함, 월드 편집기 | 모델 id | 모델 카드 편집, 패널의 모델 정보 |
| `model-preview` | 3D 모델 보관함 | 모델 id | 모델 카드 미리보기 |
| `home-preview` | 홈 화면 | 없음 | 홈 미리보기 |

### 3.4 표기 규칙

- 기본값은 주소에서 뺀다. 검색어가 비면 `q`, 모든 도서면 `status`, 선택이 없으면 `object`, 편집 중이면 `mode`, 대화상자가 없으면 `modal`·`id` 가 없다.
- 매개변수 순서를 고정해 같은 상태는 늘 같은 주소가 된다. 도서 보관함 `q, status, modal`, 모델 보관함 `q, modal, id`, 홈 화면 `modal`, 월드 편집기 `chapter, object, mode, q, modal, id`.
- 화면에 없는 매개변수와 정해진 값이 아닌 값(`status=xyz`, 모르는 `modal`, 그 화면에서 쓰지 않는 대화상자, `id` 가 필요한데 빠진 대화상자)은 버린다.
- 독자 체험 중에는 대화상자를 열 수 없으므로 `mode=reader` 와 `modal` 이 함께 있으면 `modal`·`id` 를 버린다.

### 3.5 주소 밖에서 기억하는 것

- 스크롤 위치: 방문 기록 항목의 상태(`history.state.scroll`)에 창 스크롤 값(`scrollY`)을 넣는다. 새로고침해도 항목 상태는 남으므로, 새로고침·뒤로 가기·앞으로 가기 때 그 항목의 위치로 돌아간다. 브라우저 자동 복원은 데이터를 불러오기 전에 끝나 실패하므로 `history.scrollRestoration = "manual"` 로 끄고 앱이 직접 복원한다. 주소를 받은 사람은 맨 위에서 시작한다. 편집기는 전체 화면이라 대상이 아니다.
- 편집기 패널 접힘: 브라우저 설정(`localStorage` 키 `otb-studio-panels`)에 `{ "assets": true, "tiles": false, "chapters": true, "chapter-models": true, "inspector": true }` 처럼 패널별 펼침 여부를 둔다(`true` 가 펼침, 없는 값은 펼침). 대상은 모델 보관함(`assets`), 바닥 이미지(`tiles`), 챕터(`chapters`), 챕터 모델(`chapter-models`), 선택한 오브젝트(`inspector`)다. 새로고침, 변경 적용 뒤 다시 그리기, 다른 책 열기에서 모두 유지된다. 저장소를 쓸 수 없는 환경(사생활 보호 모드 등)에서는 조용히 기본값(모두 펼침)으로 동작한다.

## 4. 이동과 방문 기록

### 4.1 기록을 쌓는 이동(push)

- 사이드바 탭 이동. 지금 보고 있는 탭을 다시 누르면 기록을 쌓지 않는다.
- 사이드바 로고. 지금은 `/admin/` 을 새로 불러오는 링크인데, 수정 키 없는 왼쪽 클릭은 도서 보관함 탭을 누른 것과 같게 앱 안에서 이동하게 바꾼다. Ctrl·가운데 클릭은 브라우저 기본 동작을 따른다.
- 표지를 눌러 편집기 열기. 새 편집기는 첫 챕터, 선택 없음, 패널 검색어 없음으로 시작하고 지금처럼 실행 취소 기록을 비운다.
- 편집기의 **← 도서 보관함**(나가기 확인을 통과한 뒤).
- 대화상자 열기(4.3절).

기록을 쌓기 전에 떠나는 항목의 스크롤 위치를 그 항목 상태에 먼저 저장한다. 새 항목은 맨 위에서 시작하되, **← 도서 보관함**은 4.5절을 따른다.

### 4.2 현재 주소만 고치는 변화(replace)

- 챕터 전환, 오브젝트 선택·해제, 독자 체험 켜기·끄기와 체험 속 챕터 이동.
- 상태 필터 변경.
- 검색어 입력(도서·모델 보관함, 편집기 패널). 입력이 250ms 멈춘 뒤 한 번 쓴다.
- 스크롤. 스크롤이 150ms 멈춘 뒤 한 번 쓰고, 기록을 쌓기 전과 `pagehide` 때 바로 쓴다. Safari 가 `replaceState` 호출 횟수를 제한하므로 멈춘 뒤에만 쓴다.
- 실행 취소·다시 실행, 삭제, 책 삭제로 책·챕터·오브젝트가 바뀌거나 사라진 경우. 지금 동작(예: 편집 중인 책을 지우면 남은 첫 책의 편집기를 연다)을 그대로 두고 주소만 따라간다.
- 불러온 직후와 보정 직후의 주소 정리(3.4절, 5절).

화면을 다시 그리는 공통 함수(`render()`)가 끝날 때 현재 상태로 만든 주소가 주소 표시줄과 다르면 고친다. 그래서 상태를 바꾸고 다시 그리는 기존 흐름은 따로 손대지 않아도 주소가 따라간다.

### 4.3 대화상자

- 버튼으로 열면 대화상자 주소로 기록을 하나 쌓고, 항목 상태에 이 기록이 대화상자용이라는 표시(`modalEntry: true`)를 남긴다.
- 닫으면(X, 바깥 클릭, Esc, 취소, 변경 적용, 삭제로 넘어가기) 표시가 있는 항목일 때 `history.back()` 으로 그 기록을 되돌린다. 창을 닫은 뒤 뒤로 가기를 누르면 창이 다시 열리지 않고 이전 페이지로 간다. 새로고침해도 항목 상태가 남으므로 새로고침으로 되살린 창도 같은 방식으로 닫는다.
- 주소를 직접 입력해 연 창은 표시가 없다. 바로 앞 기록이 관리자 화면이 아닐 수 있으므로 닫을 때 기록을 되돌리지 않고 주소에서 `modal`·`id` 만 지운다(replace).
- **새 도서 만들기**를 제출하면 기록을 되돌리지 않고, 대화상자가 차지하던 항목을 새 책의 편집기 주소로 바꾼다(replace, 표시 제거). 거기서 뒤로 가기를 누르면 도서 보관함으로 간다.
- 대화상자가 열린 채 뒤로 가기를 누르면 창만 닫힌다. 같은 편집기 안의 변화라 3D 화면을 다시 만들지 않으므로 카메라 시점이 유지된다. 앞으로 가기를 누르면 창이 다시 열린다.
- 대화상자 안에 입력하던 값과 진행 중이던 업로드 결과는 뒤로 가기로 닫으면 버려진다. 지금 X 로 닫을 때와 같다.
- `history.back()` 은 비동기다. 되돌리기가 끝나기 전에 다른 기록 쌓기나 주소 고치기가 요청되면, 되돌리기에 따른 `popstate` 를 받은 뒤에 차례로 처리한다. 그래야 새로 쌓은 기록이 되돌리기에 지워지거나 주소 고치기가 떠나는 항목에 쓰이는 일이 없다.
- 모든 iframe 은 최상위 창과 방문 기록을 공유한다. 그래서 홈 미리보기 창 안의 사용자 화면(같은 출처 iframe)은 불러올 때마다 `history.pushState` 를 `history.replaceState` 로 바꿔 끼워 방문 기록을 쌓지 않게 한다. 미리보기 안의 이동은 주소만 바꾸고, 창이 열린 채 뒤로 가기를 누르면 바로 창이 닫힌다.
- 되돌리기 뒤 1초 안에 `popstate` 가 오지 않으면 주소에서 `modal`·`id` 를 지우는 것(replace)으로 대신하고 다음 처리를 이어 간다. 미리보기 안에서 문서를 새로 여는 링크(예: 로고)를 누르면 iframe 기록이 그래도 쌓이는데, 창과 함께 iframe 이 사라진 뒤의 `history.back()` 은 그 기록만 소비하고 `popstate` 를 내지 않는다(2026-09-28 Edge 에서 확인). 이 경우 뒤로 가기 한 번이 화면 변화 없이 지나갈 수 있다.
- 새로고침 전에 쌓은 기록으로 되돌아가도 같은 문서 안의 이동(`popstate`)이고 항목 상태도 남는다(2026-09-28 Edge 에서 확인). 그래서 새로고침으로 되살린 창도 기록을 되돌려 닫는다.
- 페이지가 바뀌는 이동(탭, 편집기 열고 닫기, 뒤로 가기로 다른 페이지)에서는 열려 있던 대화상자와 확인 창을 기록 조작 없이 닫는다.

### 4.4 편집기를 떠나는 뒤로·앞으로 가기

편집기에서 다른 페이지(다른 탭, 다른 책의 편집기)의 기록으로 이동했고 저장하지 않은 변경이 있으면:
1. 떠나기 전 편집기 주소로 기록을 다시 쌓아 주소를 편집기로 되돌린다.
2. 지금의 나가기 확인 창을 띄운다. **계속 편집**은 그대로 머문다. **저장하지 않고 나가기**와 **저장 후 나가기**는 변경을 버리거나 저장한 뒤 `history.back()` 으로 원래 가려던 기록으로 간다.
3. 저장 중이면 지금처럼 "저장이 끝난 뒤 다시 이동해 주세요."를 띄우고 머문다.
4. 확인 창이 열린 채 다시 뒤로 가기를 누르면 주소만 다시 편집기로 되돌리고 창을 유지한다.

탭 사이 이동과 편집기가 아닌 페이지 사이의 뒤로·앞으로 가기는 지금처럼 확인하지 않는다. 변경 내용은 메모리에 남는다. 기록을 따라 편집기로 들어갈 때는 표지를 눌러 열 때처럼 실행 취소 기록을 비운다.

### 4.5 도서 보관함으로 돌아올 때

- 뒤로 가기로 돌아오면 그 기록의 검색어·필터(주소)와 스크롤(항목 상태)이 그대로다.
- **← 도서 보관함** 버튼은 새 기록을 쌓는다. 이때 편집기를 열기 직전의 도서 보관함 검색어·필터·스크롤을 메모리에서 되살린다.

### 4.6 뒤로·앞으로 가기 적용 규칙

`popstate` 를 받으면 주소를 읽어 보정(5절)한 뒤 현재 화면과 비교한다.
- 페이지가 다르면(화면 종류 또는 편집기의 책): 대화상자를 닫고, 상태를 주소대로 바꾸고, 다시 그린 뒤, 주소의 독자 체험·대화상자를 열고, 항목 상태의 스크롤을 복원한다.
- 같은 페이지이고 대화상자만 다르면: 대화상자만 주소에 맞게 열거나 닫는다. 편집기의 3D 화면은 다시 만들지 않는다.
- 같은 페이지인데 그 밖의 것(챕터·오브젝트·검색어·필터·독자 체험)이 다른 기록(드묾. 대화상자를 닫은 뒤 챕터를 옮기거나 독자 체험을 켜고 앞으로 가기를 누른 경우 등): 상태를 주소대로 바꾸고 다시 그린 뒤 주소의 독자 체험·대화상자를 연다.

### 4.7 독자 체험

편집기의 **▶ 독자 체험**을 누르면 주소에 `mode=reader` 를 넣고(replace), 체험 속 챕터 선택이나 이동으로 챕터가 바뀌면 `chapter` 도 바꾼다. **편집으로 돌아가기**를 누르면 `mode` 를 지우고 `chapter` 를 편집기의 챕터로 되돌린다(지금처럼 편집기 시점과 선택을 복원한다). `mode=reader` 주소로 새로고침하거나 들어오면 편집기를 그 챕터로 연 다음 체험을 시작한다. 캐릭터는 챕터 시작점에서 출발한다.

## 5. 잘못된 주소와 예외

데이터(`/api/studio`)를 불러온 뒤 주소를 검사해, 없는 항목은 가장 가까운 화면으로 바꾸고 주소도 그에 맞게 고친다(replace).

| 경우 | 처리 | 알림 |
| --- | --- | --- |
| 없는 책, 챕터가 없는 책 | 도서 보관함 | 요청한 도서를 찾을 수 없어 도서 보관함을 열었어요. |
| `chapter` 가 그 책에 없음 | 첫 챕터 | 요청한 챕터를 찾을 수 없어 첫 챕터를 열었어요. |
| `chapter` 없음 | 첫 챕터 | 없음 |
| `object` 가 그 챕터의 배치·바닥 이미지에 없음 | 선택 없음 | 요청한 오브젝트를 찾을 수 없어 선택하지 않았어요. |
| `chapter` 대화상자의 `id` 가 그 책에 없음, `model`·`model-preview` 의 `id` 가 모델 보관함에 없음 | 창을 열지 않음 | 요청한 항목을 찾을 수 없어 창을 열지 않았어요. |
| 3.4절에서 버리는 값 | 버림 | 없음 |

알림은 한 번에 하나, 책 → 챕터 → 오브젝트 → 대화상자 대상 순으로 앞선 것 하나만 띄운다.

저장하지 않은 변경이 있을 때 새로고침하면 지금처럼 브라우저가 떠나기 확인을 띄운다. 새로고침하면 마지막 임시 저장본을 불러와 같은 위치를 연다. 저장하지 않은 새 책·챕터·배치를 가리키던 주소는 위 표대로 보정된다.

로그인(비밀번호 모드): 로그인 화면에서도 주소를 바꾸지 않는다. 로그인하면 불러오기를 다시 하므로 원래 위치가 열린다. 로그아웃은 지금처럼 새로고침하므로, 다시 로그인하면 같은 위치로 돌아온다. 불러오기 실패 화면의 **다시 시도**도 같은 주소로 다시 불러온다.

되살릴 때 부작용 막기
- 홈 미리보기는 버튼으로 열 때 지금처럼 임시 저장부터 한다. 주소로 되살릴 때는 저장하지 않은 변경이 있을 때만 저장하고 연다. 불러온 직후에는 변경이 없으므로 저장 요청 없이 연다.
- 독자 체험을 되살리지 못하면(예: 3D 가속 불가) 지금처럼 오류 알림을 띄우고 편집 화면에 머물며 주소에서 `mode` 를 지운다.
- 모델 미리보기를 되살리지 못해도 지금처럼 알림을 띄우고 창은 연다.

## 6. 구성

### 6.1 `admin/route.js` (새 파일)

DOM·`history`·`localStorage` 를 모르는 순수 함수만 둔다.

- `parseRoute(pathname, search)`: 주소를 경로 객체 `{ view, bookId, chapterId, objectId, reader, q, status, modal, modalId }` 로 바꾼다. `view` 는 `books`·`home`·`models`·`settings`·`editor` 중 하나이고 쓰지 않는 필드는 `undefined` 다. 3.4절의 문법 규칙(화면별 매개변수, 정해진 값, 대화상자·`id` 조합, 독자 체험과 대화상자)을 여기서 적용한다.
- `routeHref(route)`: 경로 객체를 3.1·3.4절의 정규 주소(경로 + 쿼리 순서)로 만든다. `parseRoute(routeHref(r))` 는 `r` 과 같아야 한다.
- `resolveRoute(route, library)`: 데이터에 비춰 5절 표대로 보정한 `{ route, notice }` 를 돌려준다. `notice` 는 띄울 알림 문구 또는 `null` 이다.

### 6.2 `admin/main.js`

- 상태 → 주소: 모듈 변수(`tab`, `inEditor`, `bookId`, `chapterId`, `placementId`, 독자 체험 챕터, 도서 보관함 검색어·필터, `query`, 패널 검색어, 열린 대화상자)로 경로 객체를 만들어 `routeHref` 로 주소를 얻는다. `render()` 끝과 선택·챕터·검색·체험 알림에서 주소를 고치고(4.2절), 4.1절의 이동에서 기록을 쌓는다.
- 주소 → 상태: 불러오기(`load()`)와 `popstate` 에서 `parseRoute` → `resolveRoute` → 상태 적용 → 다시 그리기 → 독자 체험·대화상자 열기 → 스크롤 복원 순서로 적용한다(4.6절). 적용 중에 연 대화상자는 기록을 쌓지 않는다.
- 대화상자 연결: 3.3절의 대화상자를 여는 함수(`editBook`, `editChapter`, `editModel`, `previewModel`, 홈 미리보기의 `openPreview`)가 창을 만든 뒤 종류·대상을 등록한다. 등록한 창의 `close` 에서 4.3절대로 기록을 되돌리거나 주소를 고친다. 기록 조작 없이 닫아야 할 때(페이지 이동, 새 도서 제출)는 표시를 달아 구분한다.
- 기록 조작 순서 보장: 대화상자 닫기의 `history.back()` 이 끝나기 전의 기록 쌓기·주소 고치기를 `popstate` 뒤로 미루고, 1초 안에 오지 않으면 대비책으로 넘어간다(4.3절).
- 홈 미리보기 iframe: 불러올 때마다(`load`) 안쪽 `history.pushState` 를 `replaceState` 로 바꿔 끼운다(4.3절).
- 나가기 확인: 기존 `requestLeaveEditor(destination)` 를 그대로 쓰고, 4.4절의 뒤로 가기 흐름에서 `destination` 으로 `history.back()` 을 넘긴다.
- 도서 보관함: 검색어·필터를 모듈 변수로 옮겨 다시 그려도 유지하고, 편집기를 열 때 검색어·필터·스크롤을 저장해 둔다(4.5절).
- 스크롤: 3.5절과 4.2절대로 저장·복원한다.
- 로고 클릭: 4.1절.

### 6.3 `admin/workspace.js`

- `mountWorkspace` 옵션에 패널 검색어 초기값(`assetQuery`)을 받고, 모델 보관함 패널 검색 입력에 넣어 바로 걸러 보여 준다.
- 훅 추가: `search(q)`(패널 검색어가 바뀜), `reader(chapterId | null)`(독자 체험이 시작되거나 챕터를 옮기면 그 챕터 id, 끝나면 `null`). 기존 `select`, `chapter` 훅은 그대로 쓴다.
- 떠 있는 패널 다섯 개의 `<details>` 에 `data-panel` 이름을 달고, 그릴 때 `otb-studio-panels` 를 읽어 접힘을 되살리며 `toggle` 때 저장한다. 저장소 접근은 `try/catch` 로 감싼다.
- 반환 객체에 `openReader()` 를 더해 주소로 독자 체험을 시작할 수 있게 한다. `tests/workspace.mjs` 가 빌드 결과를 `return{world:…,dispose()` 정규식으로 고쳐 `window.__editorWorld` 를 만들기 때문에, 반환 객체는 `world`, `dispose` 를 이 순서로 앞에 두고 새 함수는 그 뒤에 둔다.

### 6.4 `admin/viewport-tools.js`

`inlineReader` 가 체험 속 챕터가 바뀔 때 부르는 콜백을 받는다. 지금은 선택 상자 값만 바꾼다.

### 6.5 `admin/index.html`

`<script type="module" src="./main.js">` 를 `src="/admin/main.js"` 로 바꾼다. 상대 경로는 `/admin/books/alice` 같은 깊은 주소에서 `/admin/books/main.js` 로 풀려 깨진다. Vite 는 HTML 의 `/` 로 시작하는 경로를 프로젝트 루트 기준으로 번들하므로 빌드 결과는 지금과 같다.

### 6.6 `server/index.js`

`/admin/home`, `/admin/models`, `/admin/settings`, `/admin/books/:bookId`(끝 빗금 허용)의 GET·HEAD 요청을 `/admin/index.html` 로 넘기는 미들웨어를 개발용 Vite 미들웨어와 완성본 `express.static(dist)` 앞에 하나 둔다. 개발 서버는 `appType: "mpa"` 라 깊은 경로를 제공하지 않고, 완성본 서버는 파일이 없는 경로에 404 를 주기 때문이다. 정규식은 `^/admin/(?:home|models|settings|books/[^/]+)/?$` 이고, 그 밖의 `/admin/…` 은 지금처럼 404 다. cloud 모드(Vercel)의 Express 는 `/api` 와 `/uploads` 만 받으므로 영향이 없다.

### 6.7 `admin/vercel.json`

기존 `/admin/` rewrite 다음에 네 규칙을 더한다. 끝 빗금이 붙은 주소(3.1절)도 받도록 빗금 있는 규칙을 따로 둔다.

```json
{ "source": "/admin/:section(home|models|settings)", "destination": "/admin/index.html" },
{ "source": "/admin/:section(home|models|settings)/", "destination": "/admin/index.html" },
{ "source": "/admin/books/:bookId", "destination": "/admin/index.html" },
{ "source": "/admin/books/:bookId/", "destination": "/admin/index.html" }
```

Vercel 은 정적 파일을 rewrite 보다 먼저 제공하고(vercel.json 문서의 rewrites 절), 관리자 빌드의 자산은 `/assets/…` 에 있어 이 규칙과 겹치지 않는다. 사용자 배포(`client/vercel.json`)는 바꾸지 않는다.

## 7. 검사

### 7.1 단위 검사 `tests/admin-route.test.js`

`npm test`(`node --test tests/*.test.js`)에 자동 포함된다. 작은 가짜 library(책 둘, 챕터·배치·바닥 이미지·모델 몇 개)로 확인한다.
- `parseRoute`: 경로 다섯 종류, `/`·`/admin`·끝 빗금, 모르는 경로, 화면별 매개변수 선택, 정해진 값이 아닌 값 버리기, 대화상자·`id` 조합, `mode=reader` 와 `modal` 동시 지정, 한글 검색어와 `encodeURIComponent` 가 필요한 책 id.
- `routeHref`: 기본값 생략, 매개변수 순서, 왕복(`parseRoute(routeHref(r))`).
- `resolveRoute`: 5절 표의 행마다 보정 결과와 알림 문구, 알림 우선순위.

### 7.2 브라우저 검사 `tests/admin-routes.mjs`

다른 검사처럼 완성본 서버(`startServer`)와 설치된 Microsoft Edge 로 실행한다. 포트 4353, 비밀번호 모드(처음 4351 이었으나 main 의 `tests/still-model.mjs` 가 그 포트를 써서 2026-09-29 병합 때 옮겼다). `npm run build` 뒤에 실행한다. 확인할 것:
1. 깊은 주소(`/admin/models?modal=model&id=…`)로 들어가 로그인하면 그 창이 열린다.
2. 네 탭: 누르면 경로가 바뀌고, 새로고침·직접 주소로 같은 탭이 열린다. 뒤로·앞으로 가기로 탭이 오간다.
3. 도서 보관함 검색어·상태 필터와 모델 보관함 검색어가 주소에 들어가고, 새로고침 뒤 입력칸과 걸러진 목록이 그대로다.
4. 편집기: 표지를 누르면 `/admin/books/alice?chapter=alice-1`. 챕터 전환과 오브젝트 선택이 주소를 고치되(기록 수 그대로) 새로고침 뒤 같은 챕터와 선택으로 열린다. 직접 주소로도 열린다. 패널 검색어도 유지된다.
5. 대화상자 7종: 열면 주소에 들어가고, 새로고침하면 다시 열린다. 뒤로 가기로 창만 닫히고 편집기 캔버스가 그대로이며, 앞으로 가기로 다시 열린다. X 로 닫은 뒤 뒤로 가기는 이전 페이지로 간다. 새 도서 제출 뒤 뒤로 가기는 도서 보관함으로 간다. 대화상자를 닫자마자 다른 대화상자를 열어도 기록이 꼬이지 않는다. 홈 미리보기를 되살릴 때 저장 요청(`PUT /api/studio`)이 없다. 미리보기 안의 `pushState` 는 기록을 쌓지 않아 뒤로 가기가 바로 창을 닫고, 미리보기 안에서 문서를 새로 불러온 뒤 X 로 닫아도 주소에서 `modal` 이 빠지며 이후 이동이 멈추지 않는다.
6. 독자 체험: `mode=reader` 가 들어가고, 체험 속 챕터 이동이 `chapter` 를 바꾸며, 새로고침 뒤 체험이 다시 시작된다. 끝내면 `mode` 가 빠진다.
7. 나가기 확인: 편집한 뒤 뒤로 가기를 누르면 주소가 편집기로 돌아오고 확인 창이 뜬다. 계속 편집하면 머물고, 저장하지 않고 나가면 도서 보관함으로 간다.
8. 잘못된 주소: 없는 책·챕터·오브젝트·대화상자 대상이 5절대로 보정되고 알림이 뜬다. 잘못된 값은 조용히 빠진다.
9. 스크롤: 테스트 응답(`page.route`)으로 책 18권을 채운 도서 보관함에서 스크롤한 뒤 새로고침하면 같은 위치다. 편집기에 들어갔다가 뒤로 가기와 **← 도서 보관함**으로 돌아와도 같은 위치다.
10. 패널 접힘: 바닥 이미지 패널을 접으면 새로고침, 변경 적용 뒤 다시 그리기, 다른 책 열기에서 접힌 채다.
11. 완성본 서버: `/admin/home`, `/admin/models`, `/admin/settings`, `/admin/books/alice` 는 200 과 관리자 HTML, `/admin/zzz` 는 404.
12. 페이지 오류(`pageerror`)가 없다.

## 9. 위험과 주의

- `history.back()` 비동기: 4.3절의 순서 보장이 없으면 대화상자를 닫자마자 다른 창을 여는 흐름(사람보다 빠른 자동 검사)에서 기록이 꼬인다. 7.2절 5번이 이 경우를 확인한다.
- iframe 방문 기록: 홈 미리보기 안의 `pushState` 는 막지만, 문서를 새로 여는 이동까지 막지는 못한다. 그 경우는 4.3절의 1초 대비책에 기대며 뒤로 가기 한 번이 헛돌 수 있다.
- Safari 의 `replaceState` 횟수 제한: 검색어·스크롤 쓰기를 멈춘 뒤 한 번으로 줄인다.
- Vercel rewrite 는 로컬에서 확인할 수 없다. PR 미리보기 배포에서 `/admin/models`, `/admin/books/<id>` 새로고침을 확인한다.
- 다른 세션의 상세 페이지 브랜치(`claude/detail-page-structure-27ccf7`)가 `README.md`, `docs/ADMIN-GUIDE.md`, 전환 스펙, `tests/home-admin.mjs` 를 고친다. 관리자 코드는 겹치지 않지만 문서는 병합 때 손으로 맞춰야 할 수 있다.
- 편집기 안의 변경 적용은 지금도 3D 화면을 다시 만든다(`render()`). 이 설계는 그 동작을 바꾸지 않고, 뒤로 가기로 대화상자만 닫을 때 다시 만들지 않도록만 한다.
